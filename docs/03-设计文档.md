## 1. 系统架构设计

### 1.1 整体架构

![系统架构图](images/architecture.svg)

GreenPulse 采用经典的三层架构，外加独立的 AI 智能体调度层：

```
┌─────────────────────────────────────────────────┐
│                   用户浏览器                      │
│         HTML5 / CSS3 / Vanilla JS / Leaflet      │
└──────────────────────┬──────────────────────────┘
                       │ HTTP / WebSocket
┌──────────────────────▼──────────────────────────┐
│              FastAPI 后端服务                      │
│  ┌──────────┐ ┌───────────┐ ┌──────────────┐    │
│  │ REST API │ │  数据服务  │ │ 静态文件服务  │    │
│  │ 13 端点  │ │ 查询/聚合 │ │ HTML/CSS/JS  │    │
│  └──────┬───┘ └─────┬─────┘ └──────────────┘    │
│         │           │                            │
│  ┌──────▼───────────▼─────┐                      │
│  │     SQLAlchemy ORM     │                      │
│  │   SQLite / PostgreSQL  │                      │
│  └────────────────────────┘                      │
└──────────────────────────────────────────────────┘
                       │
┌──────────────────────▼──────────────────────────┐
│          AI 智能体调度层 (APScheduler)            │
│  ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐   │
│  │专利监控│ │论文追踪│ │新闻采集│ │电池专项│   │
│  └────────┘ └────────┘ └────────┘ └────────┘   │
│  ┌────────┐ ┌────────┐                          │
│  │报告生成│ │翻译摘要│ ──────► OpenAI GPT-4o    │
│  └────────┘ └────────┘                          │
└──────────────────────────────────────────────────┘
```

### 1.2 技术选型理由

| 组件 | 选型 | 理由 |
|------|------|------|
| 前端框架 | Vanilla JS | 零依赖、快速加载、可直接打开HTML |
| 地图库 | Leaflet 1.9.4 | 轻量(42KB)、开源、丰富的插件生态 |
| 地图瓦片 | CartoDB Dark | 暗色主题、免费、全球覆盖 |
| 后端框架 | FastAPI | 异步、高性能、自动文档、类型安全 |
| ORM | SQLAlchemy 2.0 | 异步支持、成熟稳定、多数据库兼容 |
| 数据库 | SQLite (开发) / PostgreSQL (生产) | 开发简单、生产可扩展 |
| AI引擎 | OpenAI GPT-4o | 最强分析能力、多语言支持 |
| 容器化 | Docker + Compose | 标准化部署、环境隔离 |
| 云平台 | AWS (CloudFormation) | 一键部署、全球基础设施 |

## 2. UI/UX 设计

### 2.1 设计原则

1. **暗色专业**: 采用深色背景(#0a0f1a)，减少视觉疲劳，突出数据
2. **绿色能源**: 主色调采用绿色(#00c853)，象征新能源和增长
3. **信息密度**: 卡片式布局，最大化屏幕利用率
4. **渐进披露**: 首页概览 → 点击查看详情，逐层深入

### 2.5 卡片设计规范

所有卡片共享以下视觉特征：

- 背景: 渐变暗色 `linear-gradient(145deg, #111827, #0d1322)`
- 边框: 1px solid #1e293b
- 圆角: 16px (大卡片) / 10px (小卡片)
- 悬浮: translateY(-2px) + 发光阴影
- 顶部线条: 悬浮时显示绿色渐变线

## 4. AI 智能体设计

### 4.1 智能体生命周期

```
初始化 → 调度注册 → [扫描 → 处理 → AI分析 → 存储 → 等待] → 循环
```

### 4.2 智能体类层次

```
BaseAgent (抽象基类)
├── scan() → 抽象方法，采集数据
├── process() → 抽象方法，处理存储
├── analyze_with_ai() → 调用OpenAI
├── run_cycle() → 执行一个完整周期
├── start() → 启动循环
└── stop() → 停止
    │
    ├── PatentAgent (专利监控)
    │   ├── _scan_epo() → EPO OPS API
    │   └── _scan_google_patents() → SerpAPI
    │
    ├── PaperAgent (论文追踪)
    │   ├── _scan_semantic_scholar() → S2 API
    │   └── _scan_arxiv() → arXiv API
    │
    ├── NewsAgent (新闻采集)
    │   └── _scan_serpapi_news() → Google News
    │
    ├── BatterySpecialistAgent (电池专项)
    │   └── 对battery类目做深度AI分析
    │
    ├── ReportAgent (报告生成)
    │   └── _generate_weekly_report() → 周度报告
    │
    └── TranslationAgent (翻译摘要)
        └── 多语言翻译和内容摘要
```

### 4.3 AI Prompt 设计

每个智能体配备专属的 System Prompt：

| 智能体 | Prompt 角色 | 输出要求 |
|--------|------------|---------|
| 专利 | 新能源专利分析专家 | 创新点+路线分类+影响评估+对比优势+应用场景 |
| 论文 | 顶级新能源研究员 | 核心发现+方法论评估+对比+产业影响+展望 |
| 电池 | 全球顶尖电池专家 | 路线定位+性能参数+产业化可行性+竞争格局 |
| 报告 | 资深产业分析师 | 周度概览+技术突破+产业动态+投资建议 |
| 翻译 | 专业技术翻译 | 中文翻译+保持术语准确性 |
